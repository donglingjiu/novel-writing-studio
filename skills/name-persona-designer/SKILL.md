# 网文书名与人设设计

## 适用场景

输入故事思路、大纲或范本风格要求，产出可直接交付剧情结构设计师和正文写作者使用的书名候选与人设卡。目标读者群体默认对标起点中文网/番茄小说站内风格（如《明克街13号》《大王饶命》《太白金星有点忙》一类作品的命名与人设手法），除非用户另有说明。

## 工作流程

### 1. 提炼故事核心钩子

先从思路/大纲中提炼：题材类型（都市/玄幻/历史/悬疑/systeam 等）、主角身份反差点、核心爽点/卖点（金手指、身份、复仇、逆袭等）。这一步决定书名和人设的方向，缺失时向上游（hub）索要而不是自行编造设定。

### 2. 产出 3-5 个备选书名

书名要求：
- 贴合起点/番茄同类头部作品的命名套路：常见句式为「XX+职业/身份」「宿主+身份」「XX，我+能力」「重生/穿越+反差身份」等
- 每个书名标注命名逻辑一句话说明（例如"点出主角身份反差，制造悬念"）
- 避免与知名在架作品重名或过于相似
- 按"最贴合—次贴合—备选"排序输出 3-5 个

### 3. 产出人设卡

对主角和每个主要配角，逐一输出结构化人设卡，字段固定为：

- **姓名/称号**
- **身份标签**（一句话概括，便于读者秒懂人设，如"落魄书生/隐藏至尊""马甲大佬"）
- **性格关键词**（3-5 个，避免同质化滥用的"傲娇""冷酷"堆砌，给出行为化描述而非单纯标签）
- **核心动机**（驱动人物贯穿全书行动的目标，需要具体可执行，不能是空泛的"变强"）
- **金手指/能力设定**（若有）及其边界与代价，避免后期被读者/审校发现无限制的"万能金手指"
- **关系网**：与主角/其他配角的关系类型（师徒/爱恨/竞争/血缘等）与关系变化预期节点
- **成长弧线**：起点状态 → 关键转折 → 终点状态，三段式给出，供剧情结构设计师安排在具体章节

### 4. 自检清单

交付前核对：
- 人物动机是否自洽，是否存在"为了剧情硬拗"的动机断裂
- 人设是否与目标平台受众口味对齐（爽点是否清晰、身份反差是否够强）
- 关系网是否会在后续章节产生可持续的冲突张力（避免关系过早封闭导致后续无戏可写）
- 人设卡字段是否完整，供 story-bible-keeper 直接收录建档

## 输出格式

```
## 备选书名
1. 《书名一》—— 命名逻辑
2. 《书名二》—— 命名逻辑
...

## 人设卡：主角
- 姓名/称号：
- 身份标签：
- 性格关键词：
- 核心动机：
- 金手指/能力设定：
- 关系网：
- 成长弧线：

## 人设卡：配角A
...
```

## 与其他角色的协作

- 产出交给 hub 汇总确认后，流转给 plot_structure_designer 作为剧情结构设计的人物基础。
- 人设卡定稿后应同步给 story_bible_keeper 建立人物库初始条目，供后续查询核对。
